Reconciliation Processes & Diagnostics Manual

            

              Operational reference detailing each validation tool, scan depth, and storage repair procedure.
            

          

        

        

          

            
Forward Reconciliation (Fast Scan)

            

              Quickly verifies directory existence and non-zero file sizes across all catalog assets without reading archive bodies or computing cryptographic hashes.
            

          

          

            
Forward Reconciliation (Deep Scan)

            

              Performs exhaustive byte-level audits: CRC checksum tests on ZIP archives, binary STL header verification (validating 84-byte structure and triangle counts), ASCII STL validation, and SHA-256 bit-rot auditing.
            

          

          

            
Reverse Orphan Audit

            

              Scans vault storage from the physical drive upward to catch files and directories missing from the database, offering one-click deletion or automatic catalog ingestion.
            

          

          

            
Backfill Archive Inspection

            

              Runs the ArchivePeeker engine against stored archives (ZIP, RAR, 7z) to dissect internal file hierarchies, index miniature submodels, and extract thumbnail renders.
            

          

          

            
Backfill Model Previews

            

              Downloads and caches cover images to previews/<model_id>/cover.jpg using browser headers, providing full offline catalog browsing and reducing CDN network traffic.
            

          

          

            
Staging Scratch Purge

            

              Cleans abandoned .part streaming files and stranded .work/staged folders left behind by cancelled, interrupted, or failed downloads to recover fast local scratch space.
            

          

          

            
Check Path Drift & Realign

            

              Identifies legacy folder paths (bracketed IDs, unescaped whitespace, outdated designer folders) and renames them to match current sanitized storage rules while atomically updating database records.

Buffer Sizing & Network Tradeoffs

          
    
            
  • 
              Download Stream Buffer: Smaller buffers (0.25–0.5 MB) reduce RAM consumption and yield smoother real-time speed metrics. Larger buffers (2–4 MB) reduce CPU context switching and maximize sequential write performance on fast NVMe scratch drives over Gigabit internet.
            
    • 
            
  • 
              NAS Offload Buffer: SMB and NFS network file protocols incur per-packet round-trip latency. While 4 MB is optimal for 1 GbE networks (~112 MB/s), increasing to 8–16 MB dramatically reduces network protocol overhead on 2.5 GbE and 10 GbE connections, allowing transfers to achieve line speed.
            
    • 
            
  • 
              Memory Footprint: Total buffer RAM is bounded by: (Worker Concurrency × Stream Buffer) + (Offloader Concurrency × Offload Buffer).

System Architecture & Operations Guide

          

            Operational reference for storage staging, authentication pipelines, stash manifests, and catalog integrity auditing.
          

        

      

    


    

      
      

        

          
Quick Start & Core Workflow

        

        

          
The library lifecycle operates via decoupled, idempotent pipeline stages designed to resist upstream throttling and bot detection:

          
    
            
  1. 
              Configure Session Cookies: Under Settings → Session Authentication & Cookies, supply your PHPSESSID and cf_clearance tokens.
            
    2. 
            
  2. 
              Execute Library Scrape: Under Manage / Retrieve / Reconcile Assets → MMF Sync, click Launch Library Scraper. Playwright launches Chromium with stealth evasion plugins, navigates to your MMF library, intercepts data API payloads, and exports all model IDs to model_ids.txt.
            
    3. 
            
  3. 
              Ingest Model Metadata: Click Open Metadata Ingestion Pipeline, selecting your latest scrape directory. The ingestion worker computes an incremental delta, skipping already active records, populating new models, tags, and files, and caching cover previews locally.
            
    4. 
            
  4. 
              Staged Downloads & Offload: Select models from the Pending & Queue Explorer tab to queue them for fast NVMe chunk downloads and automatic verification before migration to your bulk vault.
            
    5. 
          

        

      


      
      

        

          
Two-Tier Staging & NAS Offload Architecture

        

        

          
To eliminate network file protocol lockups and protect mechanical parity arrays from high-frequency write churn, storage follows a dual-tier staging pipeline:

          

            Tier 1: High-Speed NVMe Scratch (Staging Path)

            All parallel chunk downloads, temporary streams, and archive extraction passes execute inside the local scratch folder. This guarantees that network drive latency never slows down active downloads.
          

          

            Tier 2: Cold/Archive Target Storage Pool (NAS Vault Path)

            Once all files for a model are downloaded and validated against expected archive signatures, a background offloader migrates the clean directory tree directly into the destination library path.
          

          
    
            
  • Zero Partial Files: The destination storage directory never holds corrupted or incomplete downloads.
    • 
            
  • Concurrency Isolation: Parallel transfers will not choke single-threaded network protocols or trigger disk thrashing.
    • 
          

        

      


      
      

        

          
Authentication Hierarchy (OAuth 2.0 vs. Cloudflare)

        

        

          
MyMiniFactory balances public REST APIs with Cloudflare Turnstile anti-bot gates. The engine uses a tiered authentication fallback strategy:

          

            
              

                Mechanism
                Priority
                Target & Behavior
              

            
            
              

                Authorization: Bearer
                Primary (API)
                Direct REST calls (/api/v2/objects/...). If the Bearer token expires (HTTP 401), the worker automatically strips it and falls back to session cookies.
              

              

                PHPSESSID
                Session
                Session identity cookie confirming user ownership of paid/backed objects. Required for downloading files.
              

              

                cf_clearance
                Bypass
                Cloudflare clearance token. Injected into Playwright and HTTP clients to pass Turnstile bot challenges without interactive CAPTCHAs.
              

            
          

        

      


      
      

        

          
Circuit Breaker & Unavailable Objects (Tombstones)

        

        

          
The ingestion and download engines employ proactive safeguards to prevent IP bans and avoid infinite retry loops:

          
    
            
  • 
              Rate Limiting (HTTP 429): The worker inspects the Retry-After header, logs the hold period, and sleeps execution until the rate window elapses.
            
    • 
            
  • 
              Circuit Breaker Pause (HTTP 401/403): If session cookies expire mid-transfer, downloads halt immediately and activate the warning banner, preventing wasted requests.
            
    • 
            
  • 
              Tombstone Recording (HTTP 404 / 410): Models removed or privatized by creators return 404. The ingestor marks them as [Unavailable Model <id>] with __tombstone__: true.
            
    • 
            
  • 
              Automatic Tombstone Reattempts: Because creators often re-publish missing campaigns, delta calculations intentionally re-poll tombstones on every run without skipping them as permanently complete.
            
    • 
          

        

      


      
      

        

          
Stash Management (“A pile of gray”)

        

        

          

            Stashes serve as logical staging manifests for curating printing campaigns, resin batches, or build queues before transferring files across networks or initiating disk writes.
          


          

            Absolute File Safety Guarantee:

            All stash actions are purely logical manifest operations in SQLite. Adding items, removing lines, or deleting an entire stash manifest will never delete, alter, or unlink physical archive files stored in your local staging directory or NAS vault.
          


          
Polymorphic 4-Tier Staging Hierarchy:

          
    
            
  • 
              Tier 1 — Full Model Bundles: Stages all archives, loose STLs, and documentation attached to an object directly from the catalog grid or model detail modal.
            
    • 
            
  • 
              Tier 2 — Individual Archive Files: Stages specific multi-gigabyte ZIP, RAR, or LYCHE project packages from the model files inspection modal.
            
    • 
            
  • 
              Tier 3 — Segmented Submodels: Stages discrete miniatures or character figures (e.g. Ghul B or Armored Moray Rider) discovered by the ArchivePeeker engine.
            
    • 
            
  • 
              Tier 4 — Raw Internal Meshes: Stages individual nested meshes or weapon bits directly from the archive raw file tree table.
